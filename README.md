# 行程计划器｜Product Requirements

一个面向个人与同行者的跨端旅行行程管理产品。它不是把备忘录搬进小程序，而是把散落在订单、聊天、截图和日历中的旅行信息，组织成可理解、可行动、可协作的旅程。

当前仓库只定义产品需求与约束，**不预设具体视觉界面**。后续设计者可在需求边界内探索具有鲜明识别度的交互与视觉语言。

## 产品一句话

把航班、高铁、酒店、活动和旅行资料组织成一段会随时间推进的旅程，并在手机与电脑之间持续同步。

## 当前阶段

- 阶段：原生微信小程序功能原型
- 首发形态：微信小程序
- 跨端策略：微信小程序优先，后续网页端与小程序共用账户及数据
- 首发用户：需要管理多段交通、住宿和活动信息的个人旅行者
- 非目标：在线售票、酒店预订平台、旅游内容社区

## 本地开发

仓库根目录已包含微信开发者工具项目配置，正式 AppID 写入 `project.config.json`，小程序源码位于 `miniprogram/`。

当前原型已实现：

- 旅行列表与创建旅行
- 按日期和时间排列的旅行详情
- 航班、高铁 / 火车、酒店、活动、餐饮、当地交通和自定义事项
- 行程项目的新建、编辑与删除
- 酒店城市、名称、房型、入住/退房日期手动录入
- 航班号 / 车次、起终点、日期时间、舱位 / 席别手动录入
- 每项行程可手动填写“到下一项的驾车时长”并在时间线展示
- 火车 / 高铁“待抢票”、预计开售时间、期望席别与“标记已出票”状态流转
- 基于微信本地存储的离线原型数据

导入方式：在微信开发者工具选择“导入项目”，目录选择本仓库根目录。当前界面只用于验证信息结构和交互闭环，不代表最终视觉设计。

当前版本不使用微信云开发、OCR 或地图 API，不需要配置云环境和第三方密钥。

## 核心原则

1. **旅程优先于表单**：用户看到的是一次旅行的节奏、关系和状态，而不是若干孤立记录。
2. **扫一眼就知道下一步**：任何时刻都应快速回答“我接下来去哪、几点、凭什么、要注意什么”。
3. **录入成本足够低**：字段围绕酒店、交通和行程衔接设计，全部支持可靠的手动录入与修改。
4. **信息有层级**：当下最重要的信息突出，订单号等低频信息随时可取但不制造噪声。
5. **跨端连续**：手机适合途中查看和快速修改，电脑适合集中整理；两端使用同一数据源。
6. **隐私默认安全**：证件号、订单号、同行人信息等敏感内容最小化采集、限制展示与分享。
